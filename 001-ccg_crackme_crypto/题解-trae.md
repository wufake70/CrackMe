## 一、题目是什么？

这是一个典型的 **Crackme**（"破解我"）小软件，界面有两个输入框：

```
┌─────────────────────────────────┐
│  Name:   [ KCTF            ]    │
│  Serial: [                 ]    │
│                                 │
│    [Register]     [Exit]        │
└─────────────────────────────────┘
```

我们的目标是：随意输入一个 **Name（用户名）**，然后算出对应的正确 **Serial（序列号/注册码）**，点击 Register 后弹出"注册成功"。

## 二、专业术语速查表（边看边查）

| 术语 | 通俗解释 | 在本题中的作用 |
|------|----------|----------------|
| **逆向工程 (Reverse Engineering)** | 把编译好的 `.exe` 程序"翻译"回近似源代码（C 语言）的过程 | 知道程序内部是怎么校验 Name 和 Serial 的 |
| **IDA Pro / x64dbg** | 两款最常用的逆向工具。IDA 负责"静态看代码"，x64dbg 负责"动态调试跑程序" | 我们题目里那段带 v1 v2 v3 的代码就是 IDA 反编译出来的 |
| **反编译 (Decompile)** | 把汇编语言（`mov eax, ebx`）还原成 C 代码的过程 | 拿到 `sub_401610` 等函数的"伪代码"方便阅读 |
| **反汇编 (Disassemble)** | 把机器码（`8B C3`）翻译成汇编（`mov eax,ebx`） | 反编译的前一步 |
| **MD5** | 一种**哈希算法**，把任意长度数据"压缩"成固定的 16 字节（32 个十六进制字符）。特点：① 不可逆 ② 改一个字节结果完全不同 | 把 Name 变成 16 字节的"指纹" |
| **RC4** | 一种**流加密算法**（对称加密 = 加解密用同一个密钥）。速度极快，早年用于 WiFi WEP、HTTPS（现已被淘汰） | 把 MD5 前 8 字节加密，变成 Serial 的前 8 字节（二进制） |
| **流加密 (Stream Cipher)** | 逐字节地把"明文 + 密钥流"做异或（XOR）得到密文。解密用相同密钥流再 XOR 一次就还原 | RC4 的本质 |
| **XOR (异或)** | 位运算：相同为 0，不同为 1。性质：`A ^ B = C` 则 `C ^ B = A`（自反性），所以 XOR 做加密可以直接还原 | RC4 的加解密就是 XOR |
| **RSA** | 最经典的**非对称加密/签名算法**。有两把钥匙：**公钥 (e, N)** 所有人可见，**私钥 d** 只有软件作者有。用私钥签名的数据，任何人都可用公钥验证 | Serial 后半段是"MD5 后 8 字节"的 RSA 签名（十进制数字串） |
| **非对称加密 (Asymmetric)** | 加解密用不同钥匙。公钥加密 → 私钥解密；私钥签名 → 公钥验签 | RSA 的数学特性 |
| **半素数 (Semiprime)** | 两个大素数的乘积 `N = p × q`。RSA 的安全性就建立在"给你 N 很难反推出 p 和 q"上 | 本题 N 只有 64 位（≈19 位十进制），可以被轻易分解！ |
| **欧拉函数 φ(N)** | `φ(N) = (p-1)×(q-1)`，是 1~N 中与 N 互质的数的个数。RSA 私钥计算的关键 | 由 φ(N) 算出私钥 `d = e^{-1} mod φ(N)` |
| **模逆 (Modular Inverse)** | 找一个 d 使得 `(e × d) mod φ(N) = 1`，相当于"模运算里的除法" | RSA 私钥就是 e 模 φ(N) 的逆 |
| **米勒-拉宾素性检测 (Miller-Rabin)** | 快速判断一个大数是否"几乎确定是素数"的概率算法 | 分解 N 时判断 p、q 是否真的是素数 |
| **Pollard's Rho 算法** | 快速分解大合数（特别是半素数）的随机算法，比暴力试除快得多 | 把 64 位的 N 分解成 p × q |
| **Base64** | 一种二进制 → 可打印字符的**编码**（不是加密！）。每 3 字节变 4 字符，用 A-Za-z0-9+/ 这 64 个字符 | Serial 本质是一段二进制数据，Base64 后变成你能从键盘输入的字符 |
| **KSA / PRGA** | RC4 算法的两个阶段：KSA 用密钥打乱 S 盒，PRGA 生成密钥流 | 对应反编译函数 `sub_408FF0`（KSA）和 `sub_4090F0`（PRGA） |
| **模幂 (Modular Exponentiation)** | `pow(base, exp, mod)`，快速计算 `base^exp mod mod`，是 RSA 的核心运算 | `sig = hash^d mod N`，验证是 `hash = sig^e mod N` |
| **大端序 (Big-Endian)** | 字节排列方式：高位字节放前面（和人类写数字的习惯一致） | MD5 后 8 字节 → 整数用 `int.from_bytes(bytes, 'big')` |

> 💡 **小提示**: 看不懂术语没关系，先往后看，回来再对表。

## 三、怎么入手？—— 找到"校验函数"

程序里点 `[Register]` 按钮会触发 `WM_COMMAND` 消息。在 IDA 里的 WndProc 中看到：

```c
case WM_COMMAND:
    if ( (unsigned __int16)a3 == 0x3EB )   // <-- 点击了 Register 按钮 (控件ID=0x3EB)
    {
        GetDlgItemTextA(..., 1008, &name, 101);      // 读 Name 输入框 (控件ID=1008)
        GetDlgItemTextA(..., 1007, &serial, 128);    // 读 Serial 输入框 (控件ID=1007)
        if ( sub_401610(name, serial) )              // ✨ 关键校验函数 ✨
            MessageBox("Successfully Registered!");   // 成功
        else
            MessageBox("Incorrect Serial...");        // 失败
    }
```

**结论**: 只要搞清楚 `sub_401610(name, serial)` 里面干了什么，我们就能写 Keygen（注册机）。

## 四、逐行拆解 `sub_401610` —— 校验逻辑总览

```c
int sub_401610(int name_ptr, int serial_ptr)
{
    // ① Serial 解码 (Base64)  ——  sub_401020
    decoded = sub_401020(serial_ptr, buffer, strlen(serial_ptr));
    if (decoded < 8) return 0;         // 解码后至少 8 字节
    for (i=8; i<decoded; i++)
        if (!isdigit(buffer[i])) return 0;   // 第 8 字节起必须都是数字

    // ② 算 MD5(name)  ——  sub_408340 + sub_4085F0
    MD5_Init(ctx);
    MD5_Update(ctx, name, strlen(name));
    MD5_Final(md5_digest, ctx);       // md5_digest 是 16 字节

    // ③ RC4 解密 serial 前 8 字节 == MD5[:8] ?
    uchar key[] = { 0x29,0x47,0x07,0x85,0x87, 0x33,0x25,0x44 };  // ")G\a\x85\x87" "3%D"
    uchar iv[256+2];   // RC4 的 S 盒 + i,j 状态
    sub_408FF0(key, 8, iv);          // RC4 KSA: 用密钥初始化 S 盒
    sub_4090F0(buffer, 8, iv);       // RC4 PRGA: 解密 buffer[0..7]
    if (memcmp(buffer, md5_digest, 8) != 0)   // ✋ 校验 1: 解密后必须等于 MD5 前 8 字节
        return 0;

    // ④ 后半段做 RSA 签名验证
    bignum sig      = parse_decimal(buffer + 8);     // Serial 第 9 字节起是十进制数
    bignum pub_exp  = 65537;                          // e = 0x010001 = 65537
    bignum modulus  = 0xB80A90BF53C6C979;            // N（硬编码字符串 "B80A90BF53C6C979"）
    bignum expected = 0;
    mod_exp(&sig, &pub_exp, &modulus, &expected);   // expected = sig^e mod N

    // ⑤ 把 MD5 后 8 字节转成十六进制字符串 → 再转成 bignum
    char hex_str[33];
    sub_4014F0(md5_digest + 8, 8, hex_str);         // 字节 → "97F5ABD5B49FD9A0" 这种十六进制
    bignum target = parse_hex(hex_str);              // 转成 bignum

    // ✋ 校验 2: RSA 解密结果必须等于 MD5[8:16]
    if (bignum_cmp(&expected, &target) != 0)
        return 0;

    return 1;   // ✅ 全部通过 = 注册成功
}
```

把上面一大段画成流程图就是：

```
  Name="KCTF"
      │
      ▼
   MD5()  → 16字节 = h[0]..h[15]
      │
      ├─ 前8字节 h[0..7] ── RC4加密(key固定) ──┐
      │                                          │
      ├─ 后8字节 h[8..15] ── RSA签名(d私钥) ──┐ │
      │                                        │ │
      ▼                                        ▼ ▼
  二进制 = [RC4(h[:8])] + [十进制ASCII(RSA_sig)]
      │
      ▼
  Base64 编码 = 最终 Serial 字符串 (键盘可输入)
```

> 🔑 **核心洞察**: 程序做校验是"先解密再比对"，我们做 Keygen 就要"反过来：先取期望值再加密"—— 也就是把上面每一步**正向**跑一遍，而不是像校验那样先解密再比较。

## 五、每一步详解 + 验证

### 第 1 步：MD5(Name) —— 得到 16 字节"指纹"

拿 Name = `KCTF` 举例：

```python
>>> import hashlib
>>> hashlib.md5(b"KCTF").digest().hex()
'7a1ab1c6a2999f9797f5abd5b49fd9a0'
          ↑前8字节↑    ↑后8字节↑
```

**为什么用 MD5？** 因为软件作者需要一个"用户名 → 固定且唯一的 16 字节"函数，这样即使两个用户名只差一个字母，生成的序列号也完全不同。

### 第 2 步：RC4 加密前 8 字节 —— Serial 的第一部分

反编译里有两行：

```c
qmemcpy(v14, ")G\a", 3);   // 注意 IDA 显示的 \a 是 BEL 字符 = 0x07（不是 \n=0x0A！）
v14[3] = -123;              // = 0x85  (256 - 123 = 133)
v14[4] = -121;              // = 0x87  (256 - 121 = 135)  ⚠️ 这里很容易看错！
qmemcpy(v15, "3%D", 3);     // 0x33, 0x25, 0x44
```

把两部分拼起来得到 8 字节密钥：

```
key = 29 47 07 85 87 33 25 44
     ")G \a __ __  3  %  D"
```

> ⚠️ **新手坑**: IDA 里写的负数字节要算成补码：`-123 = 0x85`，`-121 = 0x87`。我一开始把 -121 算成 0x83（算错了！），结果 Serial 一直不对，后来直接去二进制里搜 `29 47` 这两个字节才确认。**当你不确定反编译里的值时，直接去 .exe 里搜字节模式是最靠谱的办法。**

RC4 加密过程（把前 8 字节 MD5 `7a 1a b1 c6 a2 99 9f 97` 送进 RC4）：

```
RC4(key, 7a 1a b1 c6 a2 99 9f 97)  →  d2 e5 0d ba 45 10 0b 0f
```

这 8 个乱码一样的字节就是 Serial 二进制形式的前 8 字节。

### 第 3 步：RSA 签名 —— Serial 的第二部分（精髓）

RSA 在本题里用得**不安全**，因为作者把 N 选得太小了（只有 64 位）！正规 RSA 现在至少用 2048 位甚至 4096 位。

#### 3.1 拿到公钥

```c
// 反编译中的变量：
a65537           → 65537            (这就是公钥指数 e)
aB80a90bf53c6c9  → "B80A90BF53C6C979"  (这就是模数 N 的十六进制字符串)
```

所以：
```
e = 65537 = 0x10001
N = 0xB80A90BF53C6C979 = 13261571204164536697
```

#### 3.2 分解 N = p × q （破解的关键一步！）

**为什么能分解？** 因为 N 只有 64 位，在密码学上这是个**玩具级**的大小。我们用 Pollard's Rho 算法一秒就能拆开：

```
N = 13261571204164536697
  = 3533507051 × 3753090347
    ↑ p = 35 亿     ↑ q = 37 亿
```

两个因子都是素数（用 Miller-Rabin 验证过），完美 ✅

#### 3.3 算私钥 d

RSA 公式：`φ(N) = (p-1) × (q-1)`，然后 `d = e^{-1} mod φ(N)`（模逆）

```python
p = 3533507051
q = 3753090347
phi = (p-1)*(q-1) = 13261571196877939300
d = pow(65537, -1, phi) = 164714877920238073
# 验证: (65537 * 164714877920238073) % phi == 1  ✅
```

> 📚 **模逆是什么？** 就是找一个 d，使得 e × d 除以 φ(N) 余 1。相当于在模运算的世界里，d 是 e 的"倒数"。Python 3.8+ 里直接 `pow(e, -1, phi)` 就行，底层用的是扩展欧几里得算法。

#### 3.4 计算签名 sig

期望的"被签名内容"是 MD5 后 8 字节：`97 f5 ab d5 b4 9f d9 a0`。把它当成大整数（大端序，高位在前）：

```python
>>> int.from_bytes(bytes.fromhex('97f5abd5b49fd9a0'), 'big')
10949847003367987616
```

**签名 = 期望哈希的 d 次方 mod N**：

```python
sig = pow(10949847003367987616, d, N)
    = 5616897209861081805
```

验证（程序就是这么干的）：把 sig 用公钥 e 加密回去，应当等于原哈希：

```python
>>> pow(5616897209861081805, 65537, N)
10949847003367987616  ✅ 和期望一样
```

最后把签名转成十进制字符串（ASCII 数字）：
```
sig_str = "5616897209861081805"
```

### 第 4 步：拼接 + Base64

```
二进制 raw = [RC4 前 8 字节] + [sig_str 每个字符的 ASCII 值]

d2 e5 0d ba 45 10 0b 0f   35 36 31 36 38 39 37 32 30 39 38 36 31 30 38 31 38 30 35
←─── Part1 (8字节) ────→  ←─────────── Part2 (19 字节 = "5616897209861081805") ──────────→
```

> 💡 **注意 Part2 必须是数字**：反编译里的这段：
> ```c
> if ( v7 < 48 || v7 > 57 )  // 48 = '0', 57 = '9'
>     goto FAIL;
> ```
> 就是在检查第 8 字节起每个字符都是 ASCII 数字。这解释了为什么我们把 RSA 签名转成十进制数字串—— 因为程序就这么要求的！

最后用 **Base64** 编码 27 字节的 raw，得到可输入的字符串：

```python
>>> import base64
>>> raw = bytes.fromhex('d2e50dba45100b0f') + b'5616897209861081805'
>>> base64.b64encode(raw).decode()
'0uUNukUQCw81NjE2ODk3MjA5ODYxMDgxODA1'
```

### ✨ 最终答案

```
Name:   KCTF
Serial: 0uUNukUQCw81NjE2ODk3MjA5ODYxMDgxODA1
```

把这两个值填入 Crackme，点击 [Register] 应该看到 **"Successfully Registered!"** 🎉

## 六、为什么能被破解？—— 作者踩的密码学坑

这道题虽然用了 MD5 + RC4 + RSA 三重组合，看起来很吓人，但其实每个地方都"用错了"：

| 坑 | 说明 | 如果是我会怎么改 |
|----|------|-----------------|
| 🔴 RSA 只有 64 位 | 19 位十进制的 N 用 Pollard's Rho 毫秒级分解 | 至少用 2048 位（617 位十进制） |
| 🔴 RC4 密钥硬编码 | 密钥直接放在 .data 段，字符串搜索就能找到 | 密钥应该由主密钥派生，或者和硬件绑定 |
| 🔴 MD5 不加盐 | `MD5(name)` 任何人算出来都一样，完全可预测 | 至少做 `MD5(name + 作者秘钥)` |
| 🔴 RSA 直接签名裸哈希 | 没有 PKCS#1 padding，存在多种攻击面 | 至少用 `RSA-PSS` 填充 |

**给新人的启发**: 用"高级的算法名字" ≠ 安全。组合得不好，每一层都是白加。

## 八、总结 & 学习路线

这道题的知识点分布：

```
逆向工程 (40%)        密码学 (50%)        编码 (10%)
├── WndProc 消息     ├── MD5 哈希        └── Base64
├── 控件 ID 定位     ├── RC4 流加密
└── 反编译阅读       ├── RSA 原理 & 分解
                       ├── Miller-Rabin
                       └── Pollard's Rho
```

**刚接触 CTF 的新人建议按这个顺序学**：

1. **逆向入门**: 找一个简单 Crackme，跟着视频用 x64dbg 把 MessageBox 弹窗改掉（哪怕只会改一个字节也行）。
2. **IDA 看伪代码**: 不用懂每条汇编，重点看：哪里 `strcmp`/`memcmp`？比较的两个值分别从哪来？
3. **哈希 & 编码**: 熟悉 MD5/SHA1、Base64、Hex（十六进制）这三兄弟。
4. **对称加密**: 先学 XOR 本质，再学 RC4（只有几十行代码）、AES。
5. **非对称加密**: 从"为什么 N 必须是两个大素数相乘"这个问题出发，吃透 RSA 数学。
6. **练手**: CTFtime 上找 Reverse / Crypto 方向的入门题做。

祝你享受逆向和密码学带来的解谜乐趣！🎮🔓
