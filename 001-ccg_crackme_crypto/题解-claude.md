# CCG CryptoCrack Keygen 题解（新手向）

> 目标：分析一个 Windows 对话框程序（KeygenMe / Crackme），理解它验证注册码的逻辑，
> 最终写一个脚本，输入任意用户名就能算出对应的合法序列号（Serial）。

这篇题解假设你**刚接触逆向 / CTF**，所以专业名词第一次出现时都会顺带解释一下它是什么、
在这道题里起什么作用。

## 0. 名词速查表

在正式分析之前，先把会反复出现的术语列一下，后面遇到直接回来查：

| 术语 | 是什么 | 在这题里的作用 |
|---|---|---|
| **IDA / IDA Pro** | 一款反汇编工具，能把 exe 里的机器码转成汇编，甚至进一步"反编译"成接近 C 语言的伪代码 | 我们看到的这段代码就是 IDA 生成的伪代码（`sub_401610` 这种命名就是IDA没能识别出函数真名时给的默认编号） |
| **伪代码 (pseudocode)** | 反编译器猜测出来的、类似C语言但不一定100%准确的代码 | 分析的起点，但**不能全信**，有时要动态调试才能验证细节 |
| **WndProc（窗口过程函数）** | Windows GUI 程序处理消息（点击、绘制、关闭等）的核心回调函数 | `WndProc_sub_401230` 就是这个程序对话框的消息处理入口，点"确定"按钮就会走到里面 |
| **crackme / keygenme** | 专门设计给人练习逆向的小程序：前者要求你绕过校验，后者要求你写出"注册机"来算出合法密钥 | 这道题属于 keygenme，我们的最终产物就是 `keygen.py` |
| **MD5** | 一种哈希算法，输入任意长度数据，输出固定 128 位（16字节）的"指纹"。**不可逆**（没法从哈希值反推出原文），但同样的输入永远得到同样的输出 | 程序把用户名做 MD5，得到的16字节被拆成两半分别用于两条校验路径 |
| **RC4** | 一种对称流密码算法。"对称"意味着加密和解密用的是*同一个函数、同一把密钥*——用密钥把明文异或一遍能得到密文，再用同一把密钥把密文异或一遍就能拿回明文 | 程序用固定密钥对数据做一次 RC4，我们逆向时可以直接用同一个函数"反过来"用 |
| **RSA** | 一种非对称加密/签名算法。有一对密钥：公钥 `(e, N)` 大家都能看到，私钥 `d` 只有原作者才知道。用私钥"签名"的东西可以用公钥验证 | 程序里嵌入的是公钥 `(e=65537, N=一串十六进制数)`，我们需要自己"偷"出私钥 `d` 才能伪造合法签名 |
| **模幂运算 (modular exponentiation)** | 计算 `a^b mod n` 的运算，是 RSA 的核心操作 | 校验时程序算的是 `sig^e mod N` |
| **大数 / bignum** | 超出 CPU 原生整数范围（这里是32/64位）的超大整数，需要用数组模拟运算 | RSA里的数字动辄十几二十位，程序自己实现了一套大数加减乘除模的库 |
| **Base64** | 一种编码方式，把任意二进制数据转换成只包含 `A-Z a-z 0-9 + /` （以及末尾可能的`=`补位）的可打印字符串，方便在文本框、URL 里传输 | 用户在"Serial"输入框里看到/输入的字符串，其实是内部二进制数据编码后的样子 |
| **Pollard's rho 算法** | 一种分解大整数质因数的算法，比暴力试除快得多，特别适合分解几十位以内的合数 | 用来把题目给的 64 位模数 `N` 分解成两个质数 `p, q`，这是破解本题的关键一步 |
| **欧拉函数 φ(N)** | 对于 `N = p × q`（p, q是不同质数），`φ(N) = (p-1)(q-1)` | RSA 私钥就是通过这个值算出来的 |
| **模逆元 (modular inverse)** | 求一个数 `d`，使得 `e × d ≡ 1 (mod φ(N))` | 这就是 RSA 私钥指数 `d` 的定义 |
| **栈变量 / 栈帧** | 函数运行时局部变量存放的内存区域 | IDA 伪代码里 `[esp+xxh] [ebp-xxh]` 这种标注就是在告诉你变量在栈上的位置 |
| **flag** | CTF 里对"最终答案"的统称，本题里等价于"能让程序弹出成功提示框的那个 Serial 字符串" | 我们最终要算出来的东西 |

## 1. 程序结构总览

程序是一个标准 Win32 对话框程序，核心是两个函数：

```
WndProc_sub_401230   —— 对话框消息处理函数（窗口过程）
sub_401610           —— 真正的校验逻辑（点"确定"后被调用）
```

### 1.1 `WndProc_sub_401230` 在干什么

Windows GUI 程序不是从上到下顺序执行的，而是"消息驱动"的：系统会不断把各种"消息"
（鼠标点击、窗口重绘、关闭请求……）扔给这个函数，函数用一个 `switch` 分发处理：

```c
switch (a2) {   // a2 = 消息类型
  case WM_INITDIALOG:  // 对话框刚创建时
  case WM_COMMAND:      // 用户点了某个按钮/控件
  case WM_PAINT:        // 需要重绘窗口
  case WM_SYSCOMMAND:    // 系统菜单命令（这里用来处理"关于"）
  case WM_CLOSE:         // 关闭窗口
}
```

我们只关心 `WM_COMMAND` 里这一段：

```c
if ( (unsigned __int16)a3 != 0x3EB )   // 0x3EB 大概率是"确定"按钮的控件ID
    ... 
if ( GetDlgItemTextA_dword_413150(dlg_hwnd, 1008, &name_417180, 101)     // 读取控件1008(姓名框)
  && GetDlgItemTextA_dword_413150(dlg_hwnd, 1007, &serial_417100, 128) ) // 读取控件1007(序列号框)
{
    if ( sub_401610(name, serial) )
        MessageBox("成功");
    else
        MessageBox("失败");
}
```

**小结**：点确定 → 读取姓名/序列号 → 调用 `sub_401610` 做真正的校验 → 根据返回值弹窗。

这一步的意义：**帮我们快速定位到唯一需要深入分析的函数**——`sub_401610`。GUI 部分的代码
（画图、关于框之类）跟破解逻辑无关，可以直接跳过，这也是逆向分析的常见技巧：先粗看整体
结构，圈定"关键函数"，再深入细节。

## 2. 校验函数 `sub_401610` 拆解

这是核心，我们一段一段来看。

### 2.1 第一段：Base64 解码序列号

```c
v2 = _lstrlen_dword_413094(a2);           // 求序列号字符串长度
v4 = (char *)operator new(v2);            // 分配内存
v5 = sub_401020(a2, (int)v4, v3);         // 关键调用
if ( v5 < 8u )
    goto LABEL_12;   // 失败
```

`sub_401020` 内部有这几个明显特征，可以确认它是 **Base64 解码函数**：

```c
if ( (a3 & 3) != 0 )   // 输入长度必须是4的倍数——Base64编码后长度永远是4的倍数
    return 0;
...
v6 += 3;    // 每4个输入字符 -> 3个输出字节，这是Base64固定的压缩比
...
if ( *(_BYTE *)(v3 + v4 - 1) != 61 )    // 61 是字符 '=' 的 ASCII 码，检查末尾padding
    return 3 * v5;
```

**判断技巧**：看到"长度检查`&3`"、"4进3出"、"结尾判断是否为`=`（0x3D=61）"这几个特征组合
出现，基本就能确定是 Base64（这是逆向里"识别常见算法"的经验积累，见多了自然就认出来了）。

解码之后，得到一段原始字节 `v4`，长度 `v5`。

**格式检查**：从第 8 个字节开始，后面所有字节必须是 ASCII 数字 `'0'`~`'9'`（十进制值 48~57）：

```c
v6 = 8;
do {
    v7 = v4[v6];
    if ( v7 < 48 || v7 > 57 )
        goto LABEL_12;  // 失败
} while ( ++v6 < v5 );
```

**这告诉我们解码后数据的结构**：
```
[前8字节：不透明的二进制数据]  [后面全是数字字符组成的十进制字符串]
```

### 2.2 第二段：用户名做 MD5

```c
sub_408310(v11);                              // MD5_Init
sub_408340(v11, &name_417180, name的长度);      // MD5_Update(用户名)
sub_4085F0((int)v11);                          // MD5_Final
```

如何确认这是 MD5？看 `sub_4085F0`（对应 `MD5_Final`）里面：

- `(*(_DWORD*)a1 >> 3) & 0x3F` 这种运算是 MD5 标准的"补齐到 448 位（mod 512）"逻辑
- 最后调用 `sub_4088A0`（对应 MD5 的压缩函数）处理 512 位分组
- 输出恰好写了 16 字节（`a1+88` 到 `a1+103`，正好16字节）到结果缓冲区

这些都是 MD5 算法的标准实现特征。（如果不确定，也可以直接把这段汇编和开源 MD5 库的汇编
做比对，或者动态调试直接观察输出是不是等于用某个在线工具算出的 `MD5(username)`。）

**关键的栈内存布局观察**：

```c
_BYTE v12[8];   // [esp+5Ch]
_BYTE v13[8];   // [esp+64h]
```

`v12` 和 `v13` 在栈上**紧挨着**（偏移差 8 字节），而 MD5 输出正好是 16 字节。结合后面的
使用方式，可以推断：**MD5(username) 的 16 字节结果，前 8 字节落在 `v12`，后 8 字节落在
`v13`**。这种"栈变量恰好连续、拼起来正好是一个完整数据结构"的现象在 IDA 反编译结果里很
常见，是分析局部变量时要特别留意的点。

### 2.3 第三段：RC4 校验（校验路径①）

```c
qmemcpy(v14, ")G\a", 3);
v14[3] = -123;   // 0x85
v14[4] = -121;   // 0x87
qmemcpy(v15, "3%D", sizeof(v15));
```

`v14`(5字节) 和 `v15`(3字节) 又是连续的栈变量，拼起来是 8 字节固定密钥：

```
0x29 0x47 0x07 0x85 0x87 0x33 0x25 0x44
```

（`)` = 0x29，`G` = 0x47，`\a` 是转义字符表示 0x07，负数是有符号字节的十六进制显示，
`-123` 转无符号就是 `0x85`，以此类推）

```c
sub_408FF0(v14, 8, v16);              // KSA: 用8字节密钥初始化 S盒
sub_4090F0((int)v4, 8, (int)v16);     // PRGA: 用S盒加密/解密 v4 的前8字节
if ( memcmp(v12, v4, 8u) )            // 和 MD5(username) 前8字节比较
    goto LABEL_12;  // 不相等则失败
```

`sub_408FF0` 是标准的 RC4 **KSA (Key Scheduling Algorithm，密钥调度算法)**：初始化一个
256 字节的 S 盒（置换表），根据密钥把它打乱。`sub_4090F0` 是 **PRGA (Pseudo-Random
Generation Algorithm，伪随机生成算法)**：不断从 S 盒里取字节，和明文/密文异或。

**这一步的校验条件**：
```
RC4(用固定密钥, 序列号解码后的前8字节) == MD5(用户名)的前8字节
```

由于 RC4 是对称的（加密和解密是同一个操作），要伪造出合法的"前8字节"，只需要把
`MD5(username)前8字节` 再做一次 RC4（用同一把密钥）即可。

### 2.4 第四段：RSA 校验（校验路径②）

```c
sub_4071D0(v4 + 8, (int)&v17);              // 十进制数字字符串 -> 大数 v17
sub_4071D0("65537", (int)&v18);             // "65537" -> 大数 v18 (RSA公钥指数 e)
sub_406ED0("B80A90BF53C6C979", (int)&v19);  // 十六进制字符串 -> 大数 v19 (RSA模数 N)
sub_405E40(v17, v18, v19, &v20);            // v20 = v17^v18 mod v19，即 sig^e mod N

sub_4014F0(v13, 8, v21);        // MD5后8字节 -> 十六进制ASCII字符串
sub_406ED0(v21, (int)v22);       // 该字符串 -> 大数 v22
if ( sub_402290(v22[0], v20) )   // 比较 v22 (目标值) 和 v20 (sig^e mod N)
    ...失败...
```

这一段实现的正是 **RSA 签名验证**：

```
校验条件: sig^e mod N == target
其中:
  sig    = 序列号里那一串十进制数字（转成大数）
  e      = 65537  （固定公钥指数，RSA里的常见选择）
  N      = 0xB80A90BF53C6C979  （固定模数，程序硬编码的"公钥"）
  target = MD5(username) 的后8字节（当作十六进制数解析）
```

`sub_405E40` 就是**模幂运算**函数（大数版的"快速幂"算法），`sub_402290` 是**大数比较**函数
（从代码里能看到典型的"从最高位往低位逐位比较"逻辑，符号处理也很完整，是典型的大数库实现）。

**为什么这一段没法直接伪造？**

正常情况下，RSA 签名是这样生成的：持有私钥 `d` 的一方计算 `sig = target^d mod N`，验证方
只有公钥 `(e, N)`，只能算 `sig^e mod N` 看是否等于 `target`，但**没法反过来从 `target` 
算出 `sig`**——除非知道 `d`。程序里只留了 `e` 和 `N`，没有 `d`，这是 RSA 的设计初衷：
公钥可以公开，只有私钥持有者才能生成有效签名。

## 3. 破解思路：这道题的"阿喀琉斯之踵"

到这里，如果 `N` 是一个真正安全的 RSA 模数（现实中至少 2048 位，也就是十进制 600 多位），
我们就束手无策了——目前没有已知的高效算法能从 `(e, N)` 反推出 `d`。

但这道题的 `N` 只有：

```
N = 0xB80A90BF53C6C979 = 13261571204164536697
```

只有 **64 位**（十进制20位左右）。这在真实密码学场景下是完全不安全的——`N` 越小，把它
分解成两个质数 `p × q` 就越容易。用 **Pollard's rho 算法**（一种基于"生日悖论"思想的
分解算法，专门针对中等规模合数很高效），现代电脑可以在几秒内分解完成。

一旦有了 `p` 和 `q`：

```
φ(N) = (p - 1)(q - 1)          # 欧拉函数
d = e^(-1) mod φ(N)             # 求模逆元，这就是私钥指数
```

有了私钥 `d`，我们就能反过来伪造签名了：

```
sig = target^d mod N
```

这利用的是 RSA 的数学性质：`(target^d)^e mod N == target`（只要 `d` 是 `e` 关于
`φ(N)` 的模逆元，这个恒等式必然成立），完美绕过第四段的校验。

### 3.1 一个隐藏的"数学陷阱"（做题时容易踩坑的点）

实际写脚本验证时会发现：**不是所有用户名都能生成出合法序列号！**

原因在于校验代码里这一行：

```c
if ( sub_402290(v22[0], v20) )   // v22 = target, v20 = sig^e mod N
```

`v20 = sig^e mod N`，根据模运算的定义，**永远满足 `v20 < N`**。但 `v22`（也就是
`target`，MD5后8字节当作原始数值）**没有做任何取模**，它就是 MD5 后 8 字节的原始
64 位数值，取值范围是 `[0, 2^64)`。

而 `N ≈ 1.326 × 10^19`，比 `2^64 ≈ 1.845 × 10^19` 小。也就是说：

- 如果某个用户名算出来的 `target < N`：可以正常伪造 ✅
- 如果 `target >= N`（这种情况大约有 `(2^64 - N) / 2^64 ≈ 28%` 的概率发生）：
  无论 `sig` 取什么值，`sig^e mod N` 都不可能等于这个 `target`，**这个用户名从数学上
  就不可能有合法序列号** ❌

这不是我们脚本写错了，而是这道题本身在设计上的一个"暗坑"：并非任意用户名都可解。
（题目给出的示范用户名 `KCTF` 经验证 `target < N`，属于可行的那 72%。）

这也是逆向分析里一个很好的教训：**不要想当然地认为"算法逻辑通了就一定有解"，
一定要动手验证边界条件。**

## 4. 完整攻击流程总结

```
                     ┌─────────────────────┐
                     │   输入: username      │
                     └──────────┬───────────┘
                                │
                        MD5(username)
                                │
                 ┌──────────────┴───────────────┐
                 │                                │
           前8字节 first8                    后8字节 last8
                 │                                │
        RC4(固定密钥, first8)          target = int(last8, 16)
                 │                                │
        forged_first8 (8字节)          若 target >= N: 无解，换名字
                 │                                │
                 │                     分解 N = p × q  (Pollard's rho)
                 │                     φ(N) = (p-1)(q-1)
                 │                     d = e^-1 mod φ(N)
                 │                     sig = target^d mod N
                 │                                │
                 └──────────────┬────────────────┘
                                │
              拼接: forged_first8 + str(sig)  （十进制ASCII）
                                │
                          Base64 编码
                                │
                     ┌──────────┴───────────┐
                     │  输出: Serial 字符串    │
                     └───────────────────────┘
```

## 6. 给新人的几点经验总结

1. **先抓主线，再抠细节**：GUI消息处理、画图、关于框这些和破解逻辑无关的代码可以先跳过，
   优先定位到真正做校验判断的函数。
2. **识别"教科书算法"的特征比逐行读汇编更高效**：Base64的"4进3出+`=`补位"、MD5的"补齐+
   压缩函数"、RC4的"KSA+PRGA"、RSA的"模幂+大数库"，这些都是有固定套路特征的，见得多了
   一眼就能认出来，不需要逐条指令抠。
3. **栈变量的相邻关系是重要线索**：多个连续声明、偏移紧挨着的局部变量，往往是被当成
   一整块内存/结构体在用（比如这里的 `v12+v13` 拼成16字节MD5摘要）。
4. **密码学算法 ≠ 绝对安全**：题目用了"真的"MD5/RC4/RSA，但故意把 RSA 模数设得很小
   （这里只有64位），这是CTF里非常经典的手法——**攻击的往往不是算法本身，而是算法的
   参数选择或实现细节**。看到"RSA"不要慌，先看看模数有多大，如果小于100位左右，
   基本可以判断是可以被现代算法分解的。
5. **动手验证胜过纸上谈兵**：像本题"并非所有用户名都有解"这种边界情况，只有真正跑代码
   才会发现，静态看伪代码很容易忽略。写完 keygen 一定要拿多个测试用例跑一跑，
   而不是只验证一次就当作完工。
